# 체류 판정 설계하기

연속적인 손 관절 좌표에서 의도적인 점 입력을 한 번만 만들어 내는 상태 머신을 설계합니다.

## Overview

손 관절 업데이트는 사용자가 가만히 있어도 조금씩 흔들립니다. 단순히 속도가 낮은 프레임을 점으로 바꾸면 한 위치에 여러 점이 생기고, 추적이 끊긴 뒤 타이머가 잘못 이어질 수 있습니다.

이 앱은 다음 세 상태로 입력을 안정화합니다.

| 상태 | 의미 | 다음 상태로 이동하는 조건 |
| --- | --- | --- |
| `idle` | 유효한 입력을 기다림 | 위치를 받으면 `dwelling` |
| `dwelling` | 후보 위치 주변에서 체류 중 | 시간이 끝나면 `coolingDown`; 반경을 벗어나면 새 후보로 다시 시작 |
| `coolingDown` | 같은 위치의 중복 입력을 차단 | 확정 위치에서 충분히 멀어지면 `dwelling` |

## 안정 반경

후보 중심과 현재 검지 위치의 유클리드 거리가 `stabilityRadius` 이하면 같은 체류로 봅니다.

```swift
simd_distance(center, position) <= stabilityRadius
```

반경을 너무 작게 설정하면 자연스러운 손 떨림 때문에 타이머가 계속 초기화됩니다. 너무 크게 설정하면 사용자가 선을 그리기 위해 움직이는 중에도 점이 생길 수 있습니다.

## 시간 측정

체류 시간은 시스템 벽시계가 아니라 `ProcessInfo.processInfo.systemUptime` 같은 단조 증가 시각으로 측정합니다. 시간대 변경이나 시스템 시각 보정이 제스처 판정에 영향을 주지 않습니다.

```swift
let elapsed = max(0, timestamp - startedAt)
let progress = Float(min(1, elapsed / dwellDuration))
```

진행률은 렌더러에 전달해 커서의 크기로 피드백합니다. 도메인 로직은 색상이나 엔티티를 알 필요가 없습니다.

## 재활성 거리

점이 확정된 즉시 detector는 `coolingDown`으로 이동합니다. 현재 위치가 확정 위치에서 `rearmDistance` 이상 떨어졌을 때만 다음 후보를 시작합니다. 이 조건이 한 번의 긴 체류를 여러 점으로 잘못 해석하는 것을 막습니다.

모델의 `minimumPointDistance`도 별도로 유지합니다. detector의 재활성 거리는 제스처 중복 방지 규칙이고, 모델의 최소 거리는 저장되는 별자리 형상의 유효성 규칙입니다.

## 추적 손실

손 앵커, 스켈레톤, 검지 관절 중 하나라도 추적되지 않으면 `trackingLost()`를 호출합니다. detector는 즉시 `idle`로 돌아가며 진행 중인 후보 시간을 버립니다. 이미 확정한 점은 별자리 모델에 남아 있습니다.

## 그리기 상태와 별자리 분리

몰입형 공간은 그리기 꺼짐 상태로 시작합니다. 창의 버튼을 누르거나 오른손 주먹을 0.6초 유지해 그리기를 켜고 끕니다. 주먹이 감지되는 즉시 진행 중인 체류 후보를 취소하므로 상태 전환 손짓 자체가 점으로 확정되지 않습니다.

그리기를 끄면 기존 점과 선은 그대로 유지하면서 모델의 현재 별자리를 마칩니다. 다시 켠 뒤 확정되는 첫 점은 선분 없이 새로운 별자리를 시작합니다. 따라서 두 별자리 사이에 의도하지 않은 연결선이 생기지 않습니다.

## 테스트할 경계

다음 동작은 기기 없이 단위 테스트할 수 있습니다.

- 체류 시간 직전에는 점이 확정되지 않는다.
- 정확히 체류 시간이 되었을 때 점이 한 번 확정된다.
- 안정 반경을 벗어나면 타이머가 새 위치에서 시작된다.
- 냉각 상태에서는 같은 위치가 다시 확정되지 않는다.
- 재활성 거리만큼 움직이면 다음 체류가 시작된다.
- 추적 손실이나 유효하지 않은 숫자는 상태를 초기화한다.

저장소의 `Package.swift`는 이 순수 로직만 macOS 테스트 타깃으로 재사용합니다. 앱 자체의 실행 경로는 Xcode visionOS 타깃입니다.
