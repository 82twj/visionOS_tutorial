# 머무르기 판정 설계하기

계속 흔들리는 손가락 좌표에서, 사용자가 일부러 멈춘 순간만 골라 점 하나로 바꾸는 방법을 살펴봅니다.

## Overview

손 관절 좌표는 사용자가 가만히 있어도 조금씩 흔들립니다. 속도가 느린 프레임을 그대로 점으로 바꾸면 한 자리에 점이 여러 개 생기고, 추적이 끊겼다가 돌아왔을 때 시간이 엉뚱하게 이어질 수 있습니다.

그래서 `DwellDetector`는 세 가지 상태로 입력을 다룹니다. 스타터에는 이 타입의 상태와 기준값, 보조 메서드가 들어 있고, 상태를 바꾸는 `update(position:at:)`는 Chapter 3에서 직접 작성합니다.

| 상태 | 뜻 | 다음 상태로 가는 조건 |
| --- | --- | --- |
| `idle` | 유효한 위치를 기다림 | 위치가 들어오면 `dwelling` |
| `dwelling` | 한 자리에 머무르는 중 | 0.8초가 차면 점을 찍고 `coolingDown`, 1.5cm를 벗어나면 새 자리에서 다시 시작 |
| `coolingDown` | 방금 찍은 자리에서 다시 찍지 않도록 기다림 | 찍은 자리에서 3cm 넘게 멀어지면 `dwelling` |

## 흔들림 반경

머무르기를 시작한 위치와 지금 검지 위치의 거리가 `stabilityRadius`(1.5cm) 이하이면 같은 자리에 머무르는 것으로 봅니다.

```swift
simd_distance(center, position) <= stabilityRadius
```

반경이 너무 작으면 자연스러운 손 떨림만으로 시간이 계속 처음부터 다시 시작됩니다. 너무 크면 선을 그리려고 천천히 움직이는 중에도 점이 생길 수 있습니다. 점을 찍는 위치는 지금 위치가 아니라 머무르기를 시작한 `center`입니다.

## 시간 재기

머무른 시간은 벽시계가 아니라 `ProcessInfo.processInfo.systemUptime`처럼 계속 늘어나기만 하는 시각으로 잽니다. 시간대가 바뀌거나 시스템 시각이 보정돼도 판정이 흔들리지 않습니다.

```swift
let elapsed = max(0, timestamp - startedAt)
let progress = Float(min(1, elapsed / dwellDuration))
let hasReachedDwellDuration = elapsed + 1e-9 >= dwellDuration
```

`1e-9`는 0.1초씩 더한 시각이 부동소수점 오차로 0.8에 아주 조금 못 미치는 경우를 넘기기 위한 값입니다. 진행률은 렌더러로 넘어가 커서 크기로 보입니다. 감지기는 엔티티나 재질을 알 필요가 없습니다.

## 다시 찍을 수 있게 되는 거리

점을 찍으면 감지기는 바로 `coolingDown`으로 바뀝니다. 그리고 검지가 찍은 자리에서 `rearmDistance`(3cm) 이상 멀어져야 다음 머무르기를 시작합니다. 한 번 길게 머무른 것이 점 여러 개로 바뀌는 것을 이렇게 막습니다. 기존 점에 연결한 뒤에도 코디네이터가 `beginCooldown(at:)`으로 같은 상태를 만들어, 연결한 자리에 새 점이 바로 찍히지 않게 합니다.

모델의 `minimumPointDistance`(3cm)는 이것과 따로 둡니다. 감지기의 거리는 같은 손동작이 두 번 처리되지 않게 하는 규칙이고, 모델의 거리는 저장되는 별자리 모양을 지키는 규칙입니다. 예를 들어 추적이 끊겼다가 같은 자리에서 다시 머무르면 감지기는 새로 시작하지만, 모델이 너무 가까운 점을 받지 않고 제어창에 '기존 점과 너무 가까워요. 조금 더 이동한 뒤 머물러 주세요.'가 나옵니다. Simulator에서 입력 패드를 뗐다가 마지막 점 가까이를 다시 누를 때도 같은 일이 일어납니다.

## 추적이 끊겼을 때

손 앵커, 손 골격, 검지 끝 관절 중 하나라도 추적되지 않으면 코디네이터가 `cancelDwell()`을 부르고, 그 안에서 `trackingLost()`가 감지기를 바로 `idle`로 돌려 진행 중이던 시간을 버립니다. Simulator에서는 입력 패드에서 손을 뗄 때가 이 경우입니다. 이미 찍은 점은 별자리 모델에 그대로 남아 있습니다.

## 기존 점 연결 판정

기존 점에 선을 다시 잇는 동작은 스타터의 `ExistingPointConnectionDetector`가 따로 판정합니다.

- 후보는 지금 그리는 별자리의 점뿐이고, 다음 선이 시작될 점은 빠집니다.
- 그 시작점에서 먼저 3cm 이상 떨어져야 판정을 시작합니다.
- 3cm 안에 들어온 점 가운데 가장 가까운 점을 목표로 고릅니다.
- 한 번 고른 목표는 손가락이 4cm 밖으로 나갈 때까지 바꾸지 않습니다. 가까운 두 점 사이에서 목표가 왔다 갔다 하지 않게 하려는 것입니다.
- 목표 근처에서 0.8초 머무르면 연결을 알리고, 모델은 저장된 목표 점까지 선만 하나 추가합니다.

목표가 이미 시작점과 선으로 이어져 있으면 코디네이터가 기다리지 않고 바로 '이미 연결된 점이에요. 다른 기존 점을 선택해 주세요.'를 보여 줍니다. 코디네이터는 이 판정을 새 점 머무르기보다 먼저 확인합니다. 그래서 기존 점 위에서 머무른 동작이 선 연결과 새 점을 함께 만들지 않습니다.

## 버튼 전환과 별자리 나누기

몰입형 공간은 그리기가 꺼진 상태로 열리고, 제어창의 버튼으로만 그리기를 켜고 끕니다. 버튼으로 끄는 순간 진행 중인 점 찍기와 연결 머무르기를 모두 취소합니다.

그리기를 끄면 점과 선은 그대로 두고 지금 그리던 별자리를 마칩니다. 다시 켠 뒤 찍는 첫 점은 선 없이 새 별자리를 시작하므로, 두 별자리 사이에 원하지 않는 선이 생기지 않습니다.

## 테스트로 확인하는 경계

스타터의 `HandConstellationTests/DwellDetectorTests.swift`에는 다음을 확인하는 테스트 6개가 있습니다. Chapter 3에서 `update(position:at:)`를 작성한 뒤, 실행 대상을 Apple Vision Pro Simulator로 두고 **Product > Test**(Command+U)로 실행합니다.

| 테스트 | 확인하는 것 |
| --- | --- |
| `testDoesNotCommitBeforeDuration` | 0.79초에는 점을 찍지 않고 진행률만 0.9875가 됩니다 |
| `testCommitsExactlyOnceAfterDuration` | 0.8초에 점을 한 번 찍고, 같은 자리에 더 있어도 다시 찍지 않습니다 |
| `testLeavingStabilityRadiusRestartsDwell` | 2cm 움직이면 새 위치에서 0초부터 다시 셉니다 |
| `testTrackingLossCancelsCandidate` | 추적이 끊기면 진행 중이던 시간을 버립니다 |
| `testMovingFarEnoughRearmsDetector` | 찍은 자리에서 4cm 움직이면 다음 머무르기를 시작합니다 |
| `testExternalCommitStartsInCooldown` | `beginCooldown(at:)` 뒤에는 같은 자리에서 찍지 않습니다 |

스타터를 받은 직후에는 `update`가 없어서 테스트가 빌드되지 않습니다. 테스트는 Test를 실행할 때만 빌드되므로 앱 빌드(Command+B)와 실행(Command+R)에는 영향이 없습니다.

저장소의 `Package.swift`는 ARKit과 RealityKit이 필요 없는 로직(머무르기, 기존 점 연결, 별자리 모델)만 모아 macOS 테스트 대상으로 다시 씁니다. 저장소 루트에서 `swift test`를 실행하면 이 테스트 23개가 Mac에서 실행됩니다. 앱 자체는 Xcode의 visionOS 타깃으로 빌드합니다.
